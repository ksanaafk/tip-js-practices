## 4. Модель данных и функции

### Модель задачи

Каждая задача представлена объектом со следующими полями:

- `id` — уникальный положительный целочисленный идентификатор.
- `title` — название задачи длиной от 1 до 100 символов.
- `completed` — логическое значение, показывающее, выполнена ли задача.
- `priority` — приоритет задачи: `low`, `medium` или `high`.

### Назначение файлов

- `data.js` — хранение исходных наборов задач.
- `task-service.js` — функции создания, поиска, изменения и удаления задач.
- `main.js` — выполнение демонстрационных сценариев и вывод результатов.
- `checks.js` — автоматическая проверка корректности функций.

### Создание задачи — createTask()

Реализована функция `createTask(id, title, priority = "medium")`.

Функция проверяет корректность идентификатора, названия и приоритета задачи.

При успешной проверке возвращается объект:

`{ ok: true, task: {...} }`

При некорректных данных:

`{ ok: false, error: "Описание ошибки" }`

Новая задача всегда создаётся со значением `completed: false`.

### Проверка createTask()

Для проверки использован файл `checks.js`.

Успешно пройдены проверки № 01–08, включая:

- Создание задачи с явным приоритетом.
- Приоритет по умолчанию.
- Удаление пробелов по краям названия.
- Проверку допустимых и недопустимых данных.
- Создание независимых объектов.

**Результат:** 8 проверок пройдено успешно.

### Особенности реализации

**Почему id не равен индексу:**

`id` — уникальный идентификатор задачи, а индекс — её позиция в массиве. Индексы могут изменяться при удалении элементов, тогда как идентификаторы задач сохраняются.

**Почему getTaskStats возвращает число, а не строку с процентом:**

Числовое значение позволяет использовать результат в дальнейших вычислениях. Преобразование в строку с процентом выполняется только при выводе, например через `toFixed(1)`.

**Какие объекты копируются при изменении задачи:**

При изменении задачи создаётся новый массив и новый объект изменяемой задачи. Остальные объекты могут сохранять прежние ссылки. Такой подход позволяет не изменять исходные данные.


### Чтение списка и расчёт сводки

В файле `src/task-service.js` реализованы четыре функции для работы с массивом задач.

**findTaskById(tasks, id)**

Осуществляет поиск задачи по идентификатору с помощью метода `find()` и строгого сравнения `===`. Возвращает найденный объект либо `undefined`, если задача отсутствует.

**getPendingTasks(tasks)**

Использует метод `filter()` для формирования нового массива задач, у которых `completed === false`.

**getTaskTitles(tasks)**

Использует метод `map()` для формирования массива строк с названиями задач в исходном порядке.

**getTaskStats(tasks)**

Вычисляет количество всех задач, выполненных и невыполненных задач, а также процент выполнения.

Возвращает объект с полями `total`, `completed`, `pending` и `progress`.

Для пустого массива процент выполнения принимается равным `0`, что предотвращает деление на ноль.

Все функции работают с переданным массивом и не изменяют исходные данные.


### Добавление задачи — addTask()

Функция `addTask()` предназначена для добавления новой задачи в конец массива.

Корректность входных данных проверяется с помощью `createTask()`. Перед добавлением выполняется поиск существующей задачи с таким же идентификатором через `findTaskById()`.

При успешном выполнении возвращается объект `{ ok: true, tasks: новыйМассив }`.

При некорректных данных или повторяющемся идентификаторе возвращается `{ ok: false, error: "Описание ошибки" }`.

Для создания нового массива используется spread-синтаксис `[...tasks, result.task]`. Исходный массив и его объекты не изменяются.


### Изменение статуса задачи — setTaskCompleted()

Функция `setTaskCompleted()` изменяет статус выполнения задачи по её идентификатору.

Перед изменением проверяются корректность `id`, логический тип значения `completed` и наличие задачи в массиве.

Для обновления используется метод `map()` и spread-синтаксис объекта. При успешном выполнении создаются новый массив и новый объект изменяемой задачи. Исходные данные сохраняются.

**При успехе:** `{ ok: true, tasks: новыйМассив }`.

**При ошибке:** `{ ok: false, error: "Описание ошибки" }`.


### Переименование задачи — renameTask()

Функция `renameTask()` изменяет название задачи по её идентификатору.

Перед выполнением проверяются корректность `id`, строковый тип названия, его длина после удаления пробелов по краям и наличие задачи в массиве.

Для создания нового состояния используются метод `map()` и spread-синтаксис объекта `{ ...task, title: cleanTitle }`.

При успешном выполнении возвращается `{ ok: true, tasks: новыйМассив }`.

При ошибке возвращается `{ ok: false, error: "Описание ошибки" }`.

Исходный массив не изменяется. Поля `id`, `completed` и `priority` сохраняют прежние значения.


### Удаление задачи — removeTask()

Функция `removeTask()` предназначена для удаления задачи по её уникальному идентификатору.

Перед удалением проверяется корректность идентификатора и наличие задачи в массиве.

Для удаления используется метод `filter()`, который создаёт новый массив без выбранной записи и сохраняет порядок остальных элементов.

При успешном выполнении возвращается объект:

`{ ok: true, tasks: новыйМассив }`

При некорректном или отсутствующем идентификаторе возвращается:

`{ ok: false, error: "Описание ошибки" }`

Исходный массив и объекты оставшихся задач не изменяются.
